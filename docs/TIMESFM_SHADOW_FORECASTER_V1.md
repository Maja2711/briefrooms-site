# TimesFM Shadow Forecaster v1

## Purpose

TimesFM is admitted to BriefRooms only as a **research-shadow forecaster**. It is not a trading engine and has no decision authority.

Initial experiment:

- model: `google/timesfm-2.5-200m-pytorch`
- package pinned by workflow: `timesfm[torch]==2.0.2`
- instrument: EUR/USD (`EURUSD=X`)
- source data: Yahoo Finance chart
- input frequency: 30-minute bars
- context: up to 1,024 completed bars, minimum 256
- forecast horizon generated by the model: 48 future 30-minute steps
- scored checkpoints: 2 steps (1h), 8 steps (4h), 48 steps (24h trading bars)

The experiment answers one narrow question:

> Does TimesFM add prospective forecasting information for EUR/USD that is useful enough to justify later integration with BriefRooms decision research?

It does **not** assume that TimesFM predicts markets well merely because it performs well on generic time-series benchmarks.

## Data flow

```text
Yahoo EUR/USD 30m bars
        |
        v
completed-bar filter
        |
        v
TimesFM 2.5
        |
        v
frozen forecasts: 1h / 4h / 24h
        |
        v
hash-chained shadow producer ledger
        |
      time
        |
        v
future completed EUR/USD bars
        |
        v
outcomes + forecast errors
```

The producer ledger uses the existing BriefRooms `learning_ledger.append_event()` format and hash-chain verification. This gives the TimesFM experiment the same immutable event semantics needed by the later Learning Engine without giving TimesFM access to production policy.

## Anti-hindsight rules

1. No historical forecast backfill.
2. First run establishes an explicit activation boundary.
3. A forecast is written before its outcome exists.
4. A run settles only forecasts already present before it generates a new forecast set.
5. Only completed 30-minute bars are used as model context.
6. If the latest completed bar is more than 90 minutes stale, no new forecast is created.
7. Forecast events are immutable and SHA-256 hash chained through the existing Learning Ledger implementation.
8. A changed model, instrument, or interval requires a new explicit experiment version rather than silently mutating the activation contract.

## What is recorded

Each frozen forecast records:

- model/checkpoint and installed TimesFM package version,
- forecast timestamp,
- information-set context length and context start,
- origin bar timestamp and price,
- horizon in 30-minute steps,
- point forecast,
- predicted return and direction,
- mean and q10..q90 quantiles,
- `shadow=true`,
- `decision_influence=false`.

Each resolved outcome records:

- future target bar and the time its close became observable,
- actual price and actual return,
- absolute and squared forecast error,
- directional correctness,
- whether the actual value fell inside the q10-q90 interval,
- `decision_influence=false`.

Raw forecast + raw outcome are retained so later evaluation can recompute metrics rather than relying only on precomputed summaries.

## Zero-authority invariant

All of the following remain `false`:

- decision influence,
- Belief Core writeback,
- Evidence writeback,
- evidence-weight writeback,
- causal-edge writeback,
- engine-policy writeback,
- ranking writeback,
- sizing writeback,
- trade execution,
- automatic tuning,
- automatic promotion,
- historical backfill.

Therefore TimesFM cannot change BRACE, WES, BRACE-SPX, Daily EUR/USD, GPW, US Stocks, portfolio construction, position sizing, or execution.

## Durability

`.github/workflows/timesfm-shadow-forecaster.yml` restores the previous successful private artifact before every cycle. If a previous successful run exists but its state cannot be restored and verified, the workflow fails closed rather than silently creating a new history.

The cumulative private artifact contains:

- `timesfm_shadow_activation.json`
- `timesfm_shadow_ledger.jsonl`
- `timesfm_shadow_status.json`

The model cache is not part of research state.

## Validation

The pull-request CI has two independent layers:

1. deterministic unit tests using a fake forecasting runtime, covering activation, anti-hindsight, hash-chain durability, settlement, stale-data rejection and zero authority;
2. a real TimesFM 2.5 smoke test that installs the pinned official package, loads `google/timesfm-2.5-200m-pytorch`, and performs genuine inference before this experiment is considered merge-ready.

**Merge gate:** both the deterministic test job and the real-model runtime smoke job must pass on the current PR head.

## Evaluation gate

No production integration is implied by a successful workflow. The first evaluation should compare TimesFM prospectively on at least:

- MAE / normalized MAE by horizon,
- directional hit rate,
- q10-q90 empirical coverage,
- calibration of forecast intervals,
- stability by market regime and time window,
- incremental value versus the existing EUR/USD technical / Belief / hybrid research paths.

A later candidate integration should be tested as a new challenger (for example `Technical + Belief + TimesFM`) against the existing controls. TimesFM should remain excluded if it does not add measurable out-of-sample value.
